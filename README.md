# 北美渠道总看板 · North America Channel Board

零售商与代理/集成商的渠道开发看板，单文件离线 HTML + Streamlit 外壳。
数据源：`北美渠道客户整理 (6).xlsx`（零售商 65 家 / 代理集成商 60 家 / 竞品格局 47 条）。

## 访问地址

| 方式 | 地址 | 能否多人同步 |
|---|---|---|
| **共享版**（推荐） | https://na-channel-board-91303.app.workbuddy.host/?sharecode=FRAIEZBXGM | **能**。云端只对这个域名开放 |
| GitHub Pages（只读备份） | https://cyanix-dewight.github.io/north-america-channel-board/ | 不能，页面会提示「此网址不同步 · 去共享版」 |
| Streamlit | 部署后为 `https://<app-name>.streamlit.app` | 不能，同上 |

**为什么只有共享版能同步**：云端服务做「精确来源匹配」（exact Origin match）。来自未登记域名的请求会被直接返回 `403 access_denied: the request origin is not allowed for this client`，而且浏览器读不到这个响应体，只会表现为「连不上」。所以看板在打开时会先本地比对当前域名，域名不对就直接降级为本机模式并给出跳转链接，不让人对着一个永远连不上的地址排查。

⚠️ 如果以后重新创建云服务应用，`applicationId` 会变，endpoint 与白名单域名也会跟着变，此时必须同步更新 `build_v5.py` 里的 `CLOUD` 配置并重新发布，否则同步会失效。

| 开发跟进 | 可编辑的跟进记录表：阶段 / 已完成动作 / 下一步行动 / 负责人 / 计划与最近跟进 / 难点 / 预期方向 / 数据核实 |

| 渠道角色 | 代理侧专有：按「一句话简介」原文把 60 家分成分销商（14）/ 代理商（46，含厂方代表、VAR·直销、系统集成商），逐家列出判断依据原句 |
| 总部地图 | 北美总部位置与密度 |
| 客户主表 | 全字段表格 + 排序 + CSV 导出 |

顶部「零售商 / 代理 / 集成商」切换决定当前看到的是哪一类客户，页签随之显隐。

### 新增客户池（名单阶段）

除原表 125 家外，看板还带一批**新增名单**（2026-11 追加，源文件 `北美客户新增.xlsx`）。这批和原表客户有本质区别：

| | 原表客户 | 新增名单 |
|---|---|---|
| 字段 | 全字段（门店 / 体量 / 竞品 SKU / 产品线） | 只有 国家 / 客户名 / 优先级 / 简介 / 官网 / 覆盖区域 / 是否建联 |
| 显示 | 正常 | 客户名后带琥珀色「新增」标记 |
| P 码 | 原表标注 + 模型复算校准 | 只有原表标注，**不跑三因子判定** |
| 主推型号 | 有 | 无（写明「名单阶段」） |
| 合作状态 | 原表 | 统一「未合作」 |
| 负责人 | 各自指派 | 默认 **Evelyn**（改动即覆盖） |

- **分类方式**（2026-11 第二版，v1 的关键词顺序判定已废弃）：
  1. 先查人工复核表 `data/lead_classify.json`（112 条，逐条写理由），命中的直接定档；
  2. 其余按简介里**最先出现的身份名词**判：零售名词（零售商 / 电商 / 线上商城 / 门店 / 多门店…）先出现 → 零售商；渠道名词（系统集成商 / 方案商 / 分销 / 代理 / 经销 / 工程 / 安装 / 租赁…）先出现 → 代理集成商。
     这样「系统集成商…提供设计、安装与设备零售」不会因为出现「零售」二字被误判成零售商，「零售商及集成商」也不会因为出现「集成」被误判成渠道。
  3. 两类名词都没有，但简介自述是大学 / 电视台 / 医院 / 市政府 / 教会 / 球队 / 协会 / 媒体 / 制作工作室 / 软件平台 / 制造商 → 归代理侧但单独标 **终端·非渠道**（这批是用设备的甲方，不是渠道商）；
  4. 仍判不出 → **待核实**。
- **细分统计**：零售 73 / 渠道 451 / 终端·非渠道 163（合计 687 家有效名单，另 11 家与原表重名跳过）。跟进页有「新增名单细分」筛选，可一键只看渠道商或排除终端用户。
- **不参与模型分析**：「P 码判定与校准」「渠道角色」两页只统计原表客户，并在页首写明排除了多少家新增名单 —— 用空数据算三因子会得出一片假的"不一致"。
- **跟进页可按范围切换**：表格右上有「全部 / 新增名单 / 原表客户」三个按钮。
- **数据位置**：`data/source_new.json`（由 `python src/extract.py 北美客户新增.xlsx data/source_new.json` 生成），`build_v5.py` 在构建时合并进来。**不写进 `source_latest.json`**，这样 `update.py` 重跑主表时不会把它们冲掉。
- 与原表重名的会被跳过（目前 11 家，如 Walmart / Vistek / Vidcom / Unique Photo / CompSource；按「跨两张表全局同名」判断，避免同一家同时出现在零售和代理两板），避免同名客户在跟进记录里串号。
- **判定可追溯**：客户详情抽屉顶部有「分类依据」，写明是人工复核还是规则判定、依据哪个关键词。

## 更新看板

### 客户资料（走 Excel）

看板里的客户清单、P 码、体量、竞品这些是**构建时算进 HTML** 的，改 Excel 后要重建。一条命令搞定：

```bash
python update.py "C:\Users\remo\Downloads\北美渠道客户整理 (7).xlsx"
```

它会：抽取 → 打印与当前数据的差异（新增/减少/改了哪些格）→ 备份旧数据到 `data/backup/` → 写入 → 重新构建 → 跑回归测试 → 同步 `site/`、`dashboard/`、`docs/`。
回归不通过会中止并提示回滚，不会把坏数据发布出去。

只想先看看改了哪些、不写任何文件：

```bash
python update.py --check "路径\北美渠道客户整理 (7).xlsx"
```

改错了想退回上一版：

```bash
python update.py --rollback
```

改完本地重建后，**线上还是旧的**，需要我们这边重新部署一次（链接不变）。

### ⚠️ Excel 里不要动的东西

| 不能改 | 原因 |
|---|---|
| 三个工作表名：`零售商`、`代理集成商`、`头部品牌与竞品格局` | 看板按表名取数，改名会被当成新表 |
| 表头文字（如 `客户名`、`优先级`、`综合体量`、`一句话简介`、`是否在合作`、`是否建联`、`备注`） | 模型按表头名解析字段，改词就取不到值 |
| 客户名 | 跟进记录的存储主键是 `客户类型\|客户名`，改名字会让历史跟进记录对不上（变成空记录） |

加列、加行、改单元格内容都没问题。减列要小心：被看板用到的列一旦删掉，对应指标会显示「未量化 / 待核实」。

### 不需要走 Excel 的

「开发跟进」页里的阶段、已完成动作、下一步行动、负责人、日期、难点、方向、核实状态，**直接在网页上填就会同步**，不用碰 Excel，也不影响这份数据源。

## 多人协作填写（开发跟进页）

跟进记录已经不是「各存各的」了。**用共享版网址**打开时：

- 右上角有 **填写人** 输入框，填一次会记在这台浏览器上，之后每次提交都会带上你的名字（鼠标悬停行可看到「最近更新」）。
- 卡片右上角的状态角标：**云端已同步 18:37** 表示正常；**云端未连接 · 已存本机** 表示网络或服务异常，改动先存本地并自动重试。
- 任何人改动任意一格，其他人的页面**每 6 秒自动拉取一次**（切回标签页时立即拉取），不需要刷新。
- **按字段保存**：两个人同时改同一家的不同列不会互相覆盖；改同一列以最后一次提交为准。
- 写入失败会做 3 次短退避重试，仍失败则入队，每 2.5 秒再试；改动没写进云端就关页面，浏览器会弹出确认提示。

**注意**：直接用 `file://` 双击本地 HTML 打开时，不会联网，角标显示「本机记录」；用 GitHub Pages / Streamlit 等未登记域名打开时，角标显示「此网址不同步 · 去共享版」，点一下就能跳到能同步的地址。要协作必须用共享版链接。

数据存在云端表 `pipe_records`（WorkBuddy 云服务，`wbapp_AGkoQ4nhcy53ZjRenRni7X`），主键是 `客户类型|客户名`，所以 Excel 行序调整不会错位。云端表**不开放删除**：页面上的「清空记录」只清当前浏览器缓存，不会删掉同事填的内容。

## 注意

- 看板是**单文件离线**的，所有渠道数据内联在 HTML 里；更新数据必须重新构建并推送，不是实时读 Excel。
- 只有「开发跟进」页的填写内容会同步到云端；P 码、体量、竞品这些分析结果仍是构建时算好的。
- 空值一律显示为「未填写 / 未量化 / 待核实」，不填 0、不推测。
- 加元按 1 CAD = 0.73 USD 折算，属口径假设，非实时汇率。
