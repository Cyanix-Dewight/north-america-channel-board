# 北美渠道总看板 · North America Channel Board

零售商与代理/集成商的渠道开发看板，单文件离线 HTML + Streamlit 外壳。
数据源：`北美渠道客户整理 (6).xlsx`（零售商 65 家 / 代理集成商 60 家 / 竞品格局 47 条）。

## 访问地址

| 方式 | 地址 | 能否多人同步 |
|---|---|---|
| **共享版**（推荐） | https://na-channel-board-91303.app.workbuddy.host/?sharecode=FRAIEZBXGM | **能**。云端只对这个域名开放 |
| GitHub Pages（只读备份） | https://cyanix-dewight.github.io/north-america-channel-board/ | 不能，页面会提示「此网址不同步 · 去共享版」 |
| Streamlit | 部署后为 `https://<app-name>.streamlit.app` | 不能，同上 |

**为什么只有共享版能同步**：云端服务做「精确来源匹配」（exact Origin match）。来自未登记域名的请求会被直接返回 `403 access_denied: the request origin is not allowed for this client`，而且浏览器读不到这个响应体，只会表现为「连不上」。所以看板在打开时会先本地比对当前域名，域名不对就直接降级为本机模式并给出跳转链接，不让人对着一个永远连不上的地址排查。

⚠️ 如果以后重新创建云服务应用，`applicationId` 会变，endpoint 与白名单域名也会跟着变，此时必须同步更新 `build_v5.py` 里的 `CLOUD` 配置并重新发布，否则同步会失效。

### 总部地图的口径（2026-11 修订）

地图上的点有三种来源，**视觉上必须能区分**，否则会把「州中心」误读成「总部位置」：

| 精度 | 什么样的客户 | 画法 | 位置含义 |
|---|---|---|---|
| `city` | 简介里能解析到具体城市 | 实心圆 + 城市名 | 真实总部城市坐标 |
| `state` | 只解析到州 | 空心虚线圆 + 「加利福尼亚（州）」 | **该州几何中心，不是总部** |
| `province` | 只解析到加拿大省份 | 空心虚线圆 + 「不列颠哥伦比亚（省）」 | **该省几何中心，不是总部** |

配套规则：

- **不拿简介短语当城市名**：`parseHQ()` 查不到城市时，`city` 置空，原文片段只留在 `rawCity` 里供悬停追溯。之前「主营面向全美」「采用全远程模式」「主枢纽位于西海岸」「覆盖纽约-宾州」这些描述被当成城市印在地图上，位置还落在州中心。
- **同城不会被拆成两个标签**：多伦多曾有 7 家精确城市点 + 8 家省级兜底点（省份中心恰好也是多伦多），合并后是一个簇。
- **大簇不冒用单城市名**：合并了多个城市的簇（90km 内）标成「纽约一带」，悬停里列明含哪几处，不再出现整个纽约都市圈被叫成「法明代尔」。
- **标签避让按真实宽度算**：中文 9.2px/字、英文 5.4px/字（原来一律 6.6px，中文被低估 24%，避让形同虚设）；12 个候选方位都放不下就不标，悬停仍可看，完整清单在右侧「都市圈 Top」。宁可少标，不叠字。
- **州名一律中文**：`STATE_CN / PROV_CN` 反查，同一英文名取最长的中文写法（避免「加州」把「加利福尼亚州」覆盖成单字「加」）。
- 右侧「定位覆盖」拆成 `精确到城市 / 仅到州 / 仅到省 / 未定位` 四档，未定位的客户名可展开查看；简介里没写总部的一律不猜。
- 画布上限为北纬 52.6°，加拿大北部超出视野，顶部用渐隐过渡而不是硬切。

代码位置：`src/geodata.js`（`parseHQ` / `attachHQ`）、`src/views_map.js`（`cluster` / `placeLabels` / `view`）。

### 目标行业维度（2026-11 新增）

在「零售商 / 代理集成商」之上再加一层：按「一句话简介」判**客户主要服务的行业**。核心口径是**看它卖给谁，不看它怎么卖**——
摄影器材店写「面向专业摄影师与影视剧组的摄影器材零售商」，判「摄影·影像」而不是「零售·电商」；只有大型综合零售 / 电商才归「零售·电商」。

14 个档位：教育 · 摄影·影像 · 影视·广电 · 政府·公共 · 医疗·健康 · 会议·协作 · 现场活动·租赁 · 体育·电竞 · 宗教场所 · 住宅·智能家居 · 安防·监控 · 企业·办公 · 零售·电商 · 综合·多行业（另加「未标注」）。

判定规则（`src/classify_industry.py`）：

1. 场景词按权重累加（专有场景词 3 分，泛词 1 分），同一词最多计 2 次；
2. 「服务 / 面向 / 专注 / 为 ……」后 16 字内命中的行业再 +3 分（明写服务对象的优先）；
3. 首次出现位置在前 40 字内 +1 分；
4. 得分 ≥4 的类别 ≥3 个 → 「综合·多行业」（简介写「服务政府、教育与医疗」这类就落这里）；
5. 只有「零售 / 电商 / 企业 / 租赁」这种泛线索时，按证据最强者归类并在依据里注明「证据偏弱」；
6. 只写 IT / AV 集成与分销、没提行业 → 「综合·多行业」；简介里什么线索都没有 → 「未标注」，**不硬猜**；
7. 判错的写进 `data/industry_override.json`（客户名 → 结论 + 理由），优先级最高。

当前分布（823 家）：综合·多行业 108、影视·广电 137、现场活动·租赁 75、零售·电商 70、摄影·影像 63、住宅·智能家居 62、宗教 43、安防 42、企业办公 40、教育 32、政府 31、会议协作 29、体育电竞 18、医疗 13、未标注 42（5%）。

界面上：顶部筛选栏「行业」下拉、总览「目标行业分布」环形图、P 码总表与跟进表客户名旁的行业标签、客户主表独立列、客户详情里的「目标行业」区块（含判定依据与关键词）。

     这样「系统集成商…提供设计、安装与设备零售」不会因为出现「零售」二字被误判成零售商，「零售商及集成商」也不会因为出现「集成」被误判成渠道。
  3. 两类名词都没有，但简介自述是大学 / 电视台 / 医院 / 市政府 / 教会 / 球队 / 协会 / 媒体 / 制作工作室 / 软件平台 / 制造商 → 归代理侧但单独标 **终端·非渠道**（这批是用设备的甲方，不是渠道商）；
  4. 仍判不出 → **待核实**。
- **细分统计**：零售 68 / 渠道 449 / 终端·非渠道 163（合计 680 家有效名单，另 18 家与已有客户重复跳过，见下「重复客户去重」）。跟进页有「新增名单细分」筛选，可一键只看渠道商或排除终端用户。
- **不参与模型分析**：「P 码判定与校准」「渠道角色」两页只统计原表客户，并在页首写明排除了多少家新增名单 —— 用空数据算三因子会得出一片假的"不一致"。
- **跟进页可按范围切换**：表格右上有「全部 / 新增名单 / 原表客户」三个按钮。
- **数据位置**：`data/source_new.json`（由 `python src/extract.py 北美客户新增.xlsx data/source_new.json` 生成），`build_v5.py` 在构建时合并进来。**不写进 `source_latest.json`**，这样 `update.py` 重跑主表时不会把它们冲掉。
- 与原表重名的会被跳过（目前 11 家，如 Walmart / Vistek / Vidcom / Unique Photo / CompSource；按「跨两张表全局同名」判断，避免同一家同时出现在零售和代理两板），避免同名客户在跟进记录里串号。
- **判定可追溯**：客户详情抽屉顶部有「分类依据」，写明是人工复核还是规则判定、依据哪个关键词。

## 手工录入新客户（「客户录入」页）

源表之外，同事可以直接在页面里加新客户：顶部页签「客户录入」→ 填表 → 点「保存并加入看板」，**立刻写进云端**，别人 6 秒内刷到。

- **存哪儿**：云端 `customers_extra` 表（不是源表）。`北美渠道客户整理.xlsx` 每次 `update.py` 重跑都会覆盖内置数据，手工录的存进去会被冲掉；存云端既不被覆盖，也能多人共享。
- **字段**：客户类型（零售 / 代理·集成商）、客户名、国家、优先级、目标行业、负责人、官网、覆盖区域、主要品类、一句话简介、备注。只填知道的，空着就显示「未标注」，**不替你猜**。
- **合并方式**：页面启动时把这张表拉下来，由 `model.js` 并进客户列表，批次为「名单阶段」（不跑 P 码三因子、不给主推型号），细分单独一档 **手工录入**（跟进页的细分筛选里能一键只看）。
- **去重**：同名（忽略空格与大小写）不能重复录；若看板里已有同名客户，会提示直接去「开发跟进」补进度。
- **删除**：下面那张「手工录入的客户」表格里有「删除」，只删这条手工录入，源表客户不受影响。
- **实时性**：保存成功即写库；其他人靠 6 秒轮询自动更新。轮询到变化时会重建客户列表，但**不会清掉你正在填的表单**（提交前会先把输入框的值存一遍再还回来）。
- **本机打开时**（双击 HTML）：同步关闭，表单置灰并给出提示，避免白填一场。

代码位置：`src/entry.js`（视图与表单）、`src/sync.js`（`saveExtra` / `removeExtra`）、`src/model.js`（`extraRow` / `markEntries` 把云端行并进客户列表）。

## 跟进进度导入（Evelyn 的进度表）

Evelyn 用一份 Excel 记新增名单的触达情况（`Evelyn北美客户开发进度情况-*.xlsx`，列：国家 / 客户名 / 优先级 / 一句话简介 / 官网 / 覆盖区域 / 主要品类 / 当前阶段 / 已完成动作 / 下一步动作 / 负责人 / 计划跟进 / 最近跟进）。导入分两步：

```bash
python src/extract_evelyn.py "<进度表.xlsx>"   # 1) 映射成看板的记录 id → data/evelyn_sync.json
python src/push_pipe.py                        # 2) 写进云端 pipe_records（页面刷新即见）
```

- **名字怎么认**：按「去引号 / 去标点 / & → and / 去公司尾缀」归一后比对，与 `build_v5.py` 的去重同口径；归一对不上的写进 `data/pipe_alias.json`（例如 `full compass` → `Full Compass Systems`、`Camera Corner` → `Camera Corner Connecting Point`、`Applied Electronics Edmonton` → `Applied Electronics`）。
- **类型以看板为准**：进度表虽然叫「代理集成商」，里面也混着零售侧客户，所以 `ctype` 取看板自己的分类结果，不按 sheet 名走。
- **同一个客户写了两行**（`Marco Bernard` / `Marco Bernard consultant`）：留「最近跟进」更晚的那条。
- **不覆盖原表客户**：进度表里还有 16 家原本就在原表里的客户（Walmart、Vistek、Samy's Camera…），她表里多数停在「已建联」，而看板上这些已到「已合作·维护中」，直接覆盖等于把进度改回去，所以默认跳过，要覆盖加 `--all`。
- **写入通道**：`/.cloud/database/rest/pipe_records` + 发布密钥 + 精确来源匹配的 Origin 头，与页面手填完全同构，所以不需要重新发布页面。

2026-11-06 那次导入：进度表 700 行 → 680 条写进云端（612 代理 + 68 零售），16 条原表客户跳过，2 家（`Awevoke`、`Shure Incorporated`）看板上还没有。

## 抽屉里直接补跟进记录（含备注，可换行）

「开发跟进」页点客户名，右侧抽屉**最上面新增一块「跟进记录」**，四个字段都能直接写，都是多行文本框：

| 字段 | 存哪儿 | 说明 |
| --- | --- | --- |
| 已完成动作 | `pipe_records.done_action` | 与表格里的「已完成动作」列同一份数据，改哪边另一边都变 |
| 下一步行动 | `pipe_records.next_action` | 同上 |
| 开发难点 | `pipe_records.difficulty` | 同上 |
| 备注 | `pipe_records.note` | **新增列**（2026-11-06 `ALTER TABLE` 加的）。不是原表里那个「备注」——原表字段仍原样留在抽屉末尾「原表字段」区 |

- **保存时机**：离开输入框（失焦）即存，不用点保存按钮；正在输入时边框变黄，存完恢复并显示「已保存并同步 · 日期 · 填写人」。关抽屉前浏览器会先失焦，所以点「×」或遮罩都不会丢最后一笔。
- **换行**：四个字段都是 `<textarea>`，换行原样存进云端（已验证 `第一行\n第二行` 读回一致）。
- **同步通道**：与本页表格完全同构——`W.PIPE.put()` → 本机 localStorage → `W.SYNC.push()` 单字段 upsert。所以抽屉里存完，背后的表格、KPI、图表会立刻跟着刷新，别人 6 秒内刷到。
- **看得见**：填过备注的客户，姓名后会出现一个灰色「备注」小标（悬停看前 90 字），不用挨个点开抽屉。
- **CSV**：导出/导入新增「备注」一列，导出的文件可以改完直接导回来。

代码位置：`src/views_common.js`（`openDrawer` 里的 `pipeSect` + `bindDrawerEdits`）、`src/pipe.js`（`put` / `refresh` / `BACK` / `touched`）、`src/sync.js`（`COLS.note`）。

## 更新看板

### 客户资料（走 Excel）

看板里的客户清单、P 码、体量、竞品这些是**构建时算进 HTML** 的，改 Excel 后要重建。一条命令搞定：

```bash
python update.py "C:\Users\remo\Downloads\北美渠道客户整理 (7).xlsx"
```

它会：抽取 → 打印与当前数据的差异（新增/减少/改了哪些格）→ 备份旧数据到 `data/backup/` → 写入 → 重新构建 → 跑回归测试 → 同步 `site/`、`dashboard/`、`docs/`。
回归不通过会中止并提示回滚，不会把坏数据发布出去。

只想先看看改了哪些、不写任何文件：

```bash
python update.py --check "路径\北美渠道客户整理 (7).xlsx"
```

改错了想退回上一版：

```bash
python update.py --rollback
```

改完本地重建后，**线上还是旧的**，需要我们这边重新部署一次（链接不变）。

### ⚠️ Excel 里不要动的东西

| 不能改 | 原因 |
|---|---|
| 三个工作表名：`零售商`、`代理集成商`、`头部品牌与竞品格局` | 看板按表名取数，改名会被当成新表 |

## 多人协作填写（开发跟进页）

跟进记录已经不是「各存各的」了。**用共享版网址**打开时：

- 右上角有 **填写人** 输入框，填一次会记在这台浏览器上，之后每次提交都会带上你的名字（鼠标悬停行可看到「最近更新」）。
- 卡片右上角的状态角标：**云端已同步 18:37** 表示正常；**云端未连接 · 已存本机** 表示网络或服务异常，改动先存本地并自动重试。
- 任何人改动任意一格，其他人的页面**每 6 秒自动拉取一次**（切回标签页时立即拉取），不需要刷新。
- **按字段保存**：两个人同时改同一家的不同列不会互相覆盖；改同一列以最后一次提交为准。
- 写入失败会做 3 次短退避重试，仍失败则入队，每 2.5 秒再试；改动没写进云端就关页面，浏览器会弹出确认提示。

**注意**：直接用 `file://` 双击本地 HTML 打开时，不会联网，角标显示「本机记录」；用 GitHub Pages / Streamlit 等未登记域名打开时，角标显示「此网址不同步 · 去共享版」，点一下就能跳到能同步的地址。要协作必须用共享版链接。

数据存在云端表 `pipe_records`（WorkBuddy 云服务，`wbapp_AGkoQ4nhcy53ZjRenRni7X`），主键是 `客户类型|客户名`，所以 Excel 行序调整不会错位。云端表**不开放删除**：页面上的「清空记录」只清当前浏览器缓存，不会删掉同事填的内容。

### 跟进页的两个视图操作

- **点负责人负载的条形 = 只看这个人的客户**：右上「负责人负载」里每根条都可点，点一下就筛出该负责人名下的客户（表格上方出现「只看 Evelyn · 614 家 ×」的小胶囊，点 × 或再点同一条即可恢复）。筛选只作用于跟进表，不影响其它页签；切换「全部 / 新增 / 原表」或细分时若这个人已不在当前范围，筛选会自动清除，不会出现空表。点条形时其它负责人会变淡，方便看清当前在看谁。
- **收起图表 = 把纵向空间让给列表**：跟进表上方那张「开发阶段分布 + 负责人负载」可以收起来（点卡片右上角「收起图表」），收起后列表可滑动区域从约 10 行扩到约 14 行；状态记在本机浏览器，下次进来保持上次的选择。展开时表格高度是 `max(380px, calc(100vh - 215px))`，收起时是 `max(340px, calc(100vh - 400px))`。
